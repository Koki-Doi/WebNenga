# 処理負荷の見直し（2026-09-27）

全体再調査とGoogle Analyticsの詳細は [code-audit.md](code-audit.md) を参照。再調査では別モジュール `position-controls.js` の初期非表示時にも継続する更新ループを確認した。以下の静止停止の効果は `card-effects.js` 単体のもので、ページ全体のDOM更新が0になることを意味しない。

既存の作業中の変更を維持し、通常カード表示と挨拶文の採寸を改善した。

以下の20件・24件というテスト結果は各修正時点の履歴。GA4変更後の直近結果は34件成功で、現行の計測仕様と検証範囲は [GA4実装・検証記録](ga4-implementation.md) を参照。

## 変更

- `js/card-effects.js`: 落下・傾き・光沢が収束したら requestAnimationFrame を停止。マウス・タッチ・ジャイロ入力で再開し、非表示タブでは停止する。物理計算と光沢の収束も待つため、落下完了時に動きを途中で切らない。
- `.bg` の取得を初期化時の1回に集約。現在のカードは背景要素を交換せず、スタイルを更新する構造。
- ポインタの最新座標を保持し、カード領域の採寸を1フレームに1回へ集約。離脱・タッチキャンセル時には未処理座標を破棄。
- `js/message-autofit-lite.js`: 各行を書き換えて採寸する処理を、全行を測定用要素へ追加して最大幅を1回読む処理に変更。フォント・字間と既存の縮小率制限は維持。

## 確認

- `node --test tests/*.test.mjs`: 20件成功（新規3件、既存17件）。
- 疑似60Hzのテストで、静止後600フレームのDOMアクセス増加が0。201回連続したポインタ入力に対する採寸は1回。
- 入力後の目標角度への収束、離脱時の復帰、タッチキャンセル、非表示からの復帰、ジャイロ入力による再開を確認。
- ブラウザで通常表示と、空行を含む複数行の挨拶文編集・裏面表示を確認。取得したコンソールログにエラーなし。

上記の回数はテスト条件下での値。実機のFPS・CPU時間・消費電力の改善率は未計測。

## 今後の計測候補

- 3Dガチャは既に形状共有・InstancedMesh・非活動パーティクルの更新省略・終了後の描画停止がある。GPU負荷を調べる場合は実機でポスト処理と描画解像度を比較する。今回は映像品質に影響する設定を変更していない。
- CSV生成では各行ごとにハッシュ計算を待ち、作成カード一覧をlocalStorageへ書き戻している。大量行での時間を計測した上で、書き込みの一括化を検討できる。

## PCのジャイロボタン誤表示の修正（2026-09-27）

- 原因: DeviceOrientationEvent.requestPermission の存在だけでボタンを表示していた。PCでもAPIが存在する場合があり、センサーの利用対象を区別できていなかった。
- タッチ入力対応・モバイル端末判定・端末方向APIの存在を共通条件とし、ボタン表示と有効化処理の両方へ適用。デスクトップUAのiPadはMacIntelかつ複数タッチ対応として扱い、WindowsのタッチPCは対象外とした。この条件はセンサー実在の保証ではない。
- 有効化成功時は、ボタン以外からの操作でもボタンを削除。同時の許可要求と有効化後の監視登録を重複させない。許可拒否・例外時は対象端末のみボタンで再試行できる。
- `node --test tests/*.test.mjs`: 24件成功。PC・タッチPC・Mac、iPhone・iPad、API非対応、拒否・例外と再試行を追加検証。端末情報と許可結果を模擬した自動テストであり、スマートフォン実機のセンサー・許可ダイアログは未検証。
- PCのアプリ内ブラウザでも `#gyro-btn` が0件で、取得したコンソールログにエラーがないことを確認。
